## 3. Risks and conflicts for arch-design-system

| # | Risk / conflict | Recommendation |
|---|---|---|
| R1 | **Two audience code paths must agree** (FR-7, NFR-10). | Single source of rules: the `UserAudienceKeys` builder + a pure `matchesAudience(audience, keys)` + `audienceWhere(keys)`. `resolveAudienceUserIds` is written separately (set expansion) but tested against the matcher for every seed user. |
| R2 | **FR-26 per-instance `mandatoryInApp`** isn't expressible in the static registry (B9). | Two type keys (`announcement.published`, `announcement.published_ack`), or accept a static `true`. Design picks one and records it as an ADR. |
| R3 | **FR-1 "exactly as specified" vs. the needed additions** (`lastRemindedAt`, indexes, possibly `publishedAt`). | Add them as explicitly flagged additions; intake already pre-approved `lastRemindedAt`. |
| R4 | **Feed ordering by "newest"** when publishAt is null for publish-now. | Set `publishAt = now` on publish-now so one column orders everything. |
| R5 | **Status column vs. read-time visibility** (FR-16). | Visibility is computed from `publishAt`. The maintenance claim also flips SCHEDULED→PUBLISHED for the manage view. The UI should derive the display status with the same predicate, so it is correct between cron ticks. |
| R6 | **Manage-view reach** (FR-23) means resolving N audiences per page. | Per-page live resolve (pageSize ≤ 50); `ponytail:` note for a `recipientCount` snapshot later. |
| R7 | **Notification fan-out** on SCHOOL announcements (thousands of userIds in one notify). | Chunk userIds (e.g. 1,000) when calling notify. The notifiedAt claim happens before the send, so a crash mid-send loses the remainder rather than double-sending. That matches the existing quiz-release semantics; note it. |
| R8 | **Teacher PATCH re-validation** (FR-10 on PATCH). | Run `assertCanTarget` on the *resulting* audience set whenever audiences or isPublic are present in the PATCH. |
| R9 | **Orphan purge vs. drafts** (B7). | Attach files on every save, including drafts. |
| R10 | **Public endpoint abuse** (FR-31). | Paginate with the max pageSize clamp from `parsePagination`, and optionally use `rateLimit` by IP. |
| R11 | **Stats for audience changes after publish** (FR-29). | Stats use the live audience. Reads by users no longer in the audience are excluded from the percentages. Document this. |
